# 0011. Releases with cargo-dist, archives only

Status: Accepted
Date: 2026-11-18

## Context

Users install `sus` with a tool such as `mise use github:aNNdii/sus`, which downloads a
release archive. The service is then installed with `sudo $(mise which susd) install`, so
the archive must hold both binaries. The code only builds on macOS, and macOS runners are the
expensive part of CI. The crate is not published to crates.io.

## Decision

- cargo-dist (pinned to 0.34.0 in `dist-workspace.toml` and `mise.toml`) builds the
  releases.
- Targets: `aarch64-apple-darwin` and `x86_64-apple-darwin`. One `.tar.gz` per target, each
  with `sus` and `susd`, plus checksums.
- No installers (`installers = []`): no shell script, no Homebrew formula.
- `.github/workflows/release.yml` is generated by `dist generate` and not edited by hand.
  A version tag (`v0.1.0`) builds and publishes a GitHub Release; pull requests only run
  `dist plan` (`pr-run-mode = "plan"`).
- `Cargo.toml` has `publish = false` and `[package.metadata.dist] dist = true`.

## Consequences

- One install path: `mise use github:…` plus `susd install`. Building from source with
  `cargo install --path .` still works.
- Pull requests cost no macOS release builds; a broken release build shows up only on the
  tag. `ci.yml` does not run on tags, so only commits on `main` whose `check` passed should
  be tagged.
- The binaries are not signed or notarized. A browser download gets the quarantine flag and
  Gatekeeper stops it until it is cleared.

## Alternatives considered

- **Installers.** Not needed next to `mise use github:…` and `susd install`.
- **Release builds on every pull request.** Each run costs two macOS runners.
