# Contributing

Issues and pull requests are welcome. For a security problem, read [SECURITY.md](SECURITY.md)
first and don't open a public issue.

Before larger changes, open an issue so we can agree on the approach. The design and the
decisions behind it are in [docs/architecture.md](docs/architecture.md) and
[docs/adr/](docs/adr/).

## Build and test

You need macOS and [mise](https://mise.jdx.dev). `mise install` sets up the pinned tools.

```sh
mise install
mise exec -- cargo test --locked
mise exec -- cargo clippy --locked --all-targets -- -D warnings
mise exec -- cargo fmt --check
mise exec -- dist plan
```

`rust-toolchain.toml` pins Rust 1.100.0, so CI and your machine build with the same compiler.
CI runs the same checks on every pull request and also `cargo audit` against `Cargo.lock`.

The tests run the service without root on a temporary socket (`SUS_SOCKET`, `SUS_CONFIG`;
honoured only when not root), with a throwaway key and a private `ssh-agent`. They never
touch an installed `susd`. To try a change for real, build a release and install it:

```sh
cargo build --release --locked
sudo target/release/susd install --key ~/.ssh/laptop-sudo-sign-2026.pub
```

## Pull requests

- One topic per pull request, with a test for every behaviour change.
- All checks above pass.
- Update the docs when behaviour changes: `README.md`, `docs/`, and a new ADR in
  `docs/adr/` for a design decision.
- Keep dependencies few and pinned with `=` in `Cargo.toml`.

## Releases

Push a version tag (`v0.1.0`). `.github/workflows/release.yml` builds both macOS archives
and publishes a GitHub Release. The workflow is generated by `dist generate`; don't edit it
by hand. Change `dist-workspace.toml`, then run `dist generate` again. Pull requests only run
`dist plan`.

Tag only commits on `main` whose CI passed: the release workflow does not wait for CI.

## Renaming

Every name the running code uses (binaries, socket, label, paths, namespace) lives in
`src/names.rs`. The build and the docs repeat it, so a rename touches:

1. `src/names.rs`: the `name!` macro, plus the `"SUS"` prefix of `ENV_SOCKET` and
   `ENV_CONFIG` (a macro can't uppercase, so it is spelled out).
2. `Cargo.toml`: the package name (`sus-cli`), the `repository` URL, the `[lib]` name and
   both `[[bin]]` names. Then `cargo build` updates `Cargo.lock`. Renaming the files in
   `src/bin/` is optional; they call `sus::client_main` and `sus::daemon_main`, so the lib
   name changes there too.
3. `tests/`: `use sus::` and `CARGO_BIN_EXE_sus` / `CARGO_BIN_EXE_susd`.
4. The comment in `dist-workspace.toml`, and the docs: `README.md` (title, examples, paths,
   `mise use github:…`), `SECURITY.md`, `docs/architecture.md`, `docs/configuration.md`,
   `docs/security.md`, `docs/comparison.md` and the ADRs in `docs/adr/`.

`cargo test` catches most misses: `tests/names.rs` checks the binary names, the env prefix
and that no name literal hides in `src/` outside `names.rs`. A renamed `susd` has a new
label and new paths, so run the old `susd uninstall` first.
